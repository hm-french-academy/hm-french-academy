# بنك الأسئلة المركزي — خطة التنفيذ

## النطاق
بنك موحد للابتدائي والإعدادي والثانوي. هذا الفرع يحتوي واجهة معاينة مستقلة وبيانات تجريبية محلية؛ لا يكتب إلى قاعدة البيانات الإنتاجية بعد.

## حدود الأمان
- لا يستبدل أي درس أو امتحان أو لعبة أو صفحة قائمة.
- تعديلات المعاينة في localStorage، مع استيراد وتصدير JSON.
- الأسئلة الحالية أمثلة توضيحية وليست محتوى رسميًا من كتاب مدرسي.
- لا تربط الواجهة بتدفق الطلاب قبل اعتماد سياسات قاعدة البيانات وفصل مفاتيح الإجابات.

## النموذج المقترح
1. question_bank_items: المرحلة، الصف، الفصل، المنهج، الوحدة، الدرس، نوع السؤال، الصعوبة، الحالة، نص السؤال، الاختيارات، الدرجة، بيانات المصدر، الوسوم، منشئ السؤال ومراجعه والإصدار.
2. question_bank_answer_keys: مفتاح الإجابة والتفسير والمتغيرات المقبولة؛ منفصل عن بيانات السؤال التي يراها الطالب.
3. question_bank_attempts: المستخدم، السؤال، الإجابة المرسلة، الدرجة، الزمن والتاريخ؛ لا يرى الطالب إلا محاولاته.
4. question_bank_sources: عنوان المصدر والناشر والطبعة والصفحة ونوع المصدر وحالة المراجعة وحقوق الاستخدام.

## الأمن قبل الإنتاج
- تفعيل RLS على كل الجداول المكشوفة.
- إدارة الإنشاء والتعديل والنشر والأرشفة للمستخدمين الموجودين في public.admin_users فقط.
- الطلاب يرون الأسئلة المنشورة المسموح بها وفق المنهج والصلاحيات.
- لا تعرض الإجابات الصحيحة مباشرة في واجهة الطالب؛ يتم التصحيح عبر RPC أو Edge Function آمن على الخادم.
- تسجيل المحاولات لكل مستخدم، وفحص سياسات الوصول، وتشغيل Supabase security advisors قبل النشر.

## مراحل العمل
1. حصر الأسئلة والاختبارات الحالية عبر جميع الصفوف.
2. استيراد الأسئلة بمصدر ومعرّف ثابت، دون تكرار.
3. توحيد التصنيفات ومراجعة الإجابات واكتشاف المكرر.
4. دورة حياة: مسودة ← مراجعة أكاديمية ← منشور ← مؤرشف.
5. ربط الواجهة بقاعدة البيانات المشتركة بعد اعتماد المخطط وسياسات الأمان.
6. إضافة التدريب والاختبارات المجمعة دون تغيير تدفق الدروس الحالي.
